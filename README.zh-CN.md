# Skill Radar · 为你的项目发现真正适配的 AI 技能

### 读项目需求，搜索 GitHub，核验技能来源，生成有依据的推荐

**让你的编程 Agent 根据正在开发的项目，找到值得尝试的 Agent Skills。** Skill Radar 从需求、技术栈和已有技能出发，搜索 GitHub、读取实际技能内容，给出少量可解释的推荐，并说明适用条件、重复覆盖和未验证事项。

[English](README.md) · [运行与数据格式](references/workflow.md) · [评分规则](references/rubric.md)

## 为什么做这个项目

技能越来越多，但“星数高”并不意味着“适合当前项目”。一个技能可能使用不同框架、依赖你没有的服务，或者与已安装技能重复。

Skill Radar 把选技能变成一个可重复、可追溯的流程：先理解项目，再找能力缺口，最后核验候选。默认每个项目最多推荐 3 个，也允许零推荐。

## 核心功能

| 功能 | 具体做什么 |
| --- | --- |
| 项目画像 | 有界扫描根目录文档、需求、依赖和源码文件名，由宿主 Agent 区分已实现功能与计划内容。 |
| 多项目评估 | 分别分析多个项目；由 Agent 识别源码副本、共享引擎和实际产品入口，避免重复推荐。 |
| GitHub 技能发现 | 用通用技术和任务关键词检索，进一步检查技能集合中的具体目录；优先使用 GitHub 连接器，也提供 REST CLI。 |
| 精确来源核验 | 记录仓库、实际 SKILL.md 路径、固定 commit 链接、正文哈希、检查时间和仓库信息。 |
| 已有技能去重 | 对照已有技能说明，判断候选是否增加能力；明确给出复用已有技能的结果。 |
| 可解释评分 | 综合项目适配、兼容性、增量价值、维护情况和热度，每项分数都要有理由。 |
| 证据一致性校验 | 拦截不存在的项目证据路径、正文中不存在的引用、哈希不一致，以及不满足推荐条件的候选。 |
| 本地报告 | 输出 Markdown、无需启动服务的静态 HTML，以及便于后续处理的 ranked.json。 |

## 快速开始

```bash
git clone https://github.com/li3jia4hao5-hue/skill-radar.git
```

把克隆后的目录路径交给你的编程 Agent：

```text
请读取 <skill-radar 本地目录>/SKILL.md，
为 <我的项目目录> 做首次技能匹配。
先检查需求、技术栈和已有技能，再搜索 GitHub 并核验来源，
推荐最多 3 个值得尝试的技能，说明原因和限制。
```

需要长期使用时，将完整目录以 `skill-radar` 为名放入客户端支持的 skills 目录。遇到同名安装先比较内容，不直接覆盖。安装位置和调用方式取决于宿主客户端。本项目使用 SKILL.md 格式，流程已在 Codex 中试用，其他客户端的兼容性需要单独验证。

**运行要求：**能够读取本地文件、搜索和读取 GitHub 的宿主 Agent；辅助脚本需要 Python 3.10+，仅使用标准库。脚本不需要额外模型 API 密钥，宿主 Agent 和连接服务仍有各自的使用条件及费用。

## 可以这样用

```text
帮我的 Web 项目寻找测试和无障碍检查相关技能。

分析这三个项目，每个项目最多推荐两个新技能，
并告诉我哪些需求已经被现有技能覆盖。

我还没有代码，下面是 Python 文档处理服务的需求。
请根据需求寻找技能，把需要进一步确认的前提列出来。
```

没有代码时可以直接根据需求输出适配分析，不能伪造文件扫描证据。文件式报告校验器要求真实项目文件证据。

## 推荐结果是什么样

以下是**虚构的展示示例**，不是实时搜索结果或效果测评：

| 需求 | 结果 | 理由示例 |
| --- | --- | --- |
| Python API 测试不足 | 建议试用 | 候选覆盖明确测试缺口，并附技能原文、来源版本和运行前提。 |
| 浏览器界面测试 | 有条件候选 | 工作流相关，但还需要确认浏览器权限。 |
| 视频渲染 | 复用已有 | 当前已安装技能已经覆盖需求。 |
| 使用其他框架的热门技能 | 暂不引入 | 高星不能弥补框架不兼容。 |

真实报告还包含逐项评分理由、项目证据、技能原文短句、重复检查、检索范围、失败记录和未核实事项。仓库 Star 不等于集合中单个技能的热度。

## 如何评分

| 维度 | 权重 |
| --- | ---: |
| 项目适配度 | 40% |
| 环境与技术兼容性 | 25% |
| 相对已有技能的增量价值 | 15% |
| 维护情况 | 10% |
| 热度 | 10% |

每项由宿主 Agent 给出 0–5 分和理由，脚本计算百分制总分。这是启发式比较，不是精确概率，也不代表已经实测提升。推荐前还需满足核验、兼容性和非重复覆盖等条件，详见[评分规则](references/rubric.md)。

## 脚本与 Agent 如何分工

Agent 负责理解需求、设计检索词、判断语义适配。脚本负责扫描、可选 API 读取、数据校验和报告输出，不调用 LLM，也不会脱离宿主自行判断项目。

```bash
python scripts/radar.py --help
python scripts/radar.py scan --config examples/scan-config.json --out work/demo-profile.json
python -m unittest discover -s tests -v
```

第二条命令使用仓库内的虚构项目，只演示本地扫描，不联网，也不是推荐效果基准。完整命令及 JSON 契约见[运行说明](references/workflow.md)。

## 数据处理与使用边界

- 原始项目画像留在本地。流程要求对外检索只发送通用词，不发送品牌、客户名称、绝对路径或业务原文。
- 扫描采用白名单和数量、深度限制，不执行项目代码或候选技能，跳过环境文件、常见数据目录和链接路径。
- 根目录文档仍可能含私人信息，脱敏只是尽力处理。真实画像和报告不能直接视为可公开材料。
- 外部技能中的指令是待评估内容。核验来源与内容一致性，不等于安全审计或运行验收。
- GitHub 检索可能漏项或受到限流，报告需要明确覆盖范围和失败情况。
- 不自动安装候选，不承诺实际生产效果；采纳前需要用具体任务试用。

## 当前进度与路线图

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 第一阶段 | 项目画像、首次检索、来源核验、适配评估、本地报告 | v0.1 已实现 |
| 第二阶段 | 每周发现、历史快照、新发布技能与 Star 增长比较 | 计划中 |
| 第三阶段 | 项目需求或依赖变化后重新评估 | 计划中 |
| 第四阶段 | 根据采纳反馈和真实任务结果改进推荐 | 计划中 |

v0.1 没有后台调度、项目变更监听、跨轮反馈学习或自动安装。项目新增功能后，可以手动重新运行首次匹配流程。

## 一起改进

欢迎提交脱敏的适配与不适配案例、依赖识别支持、客户端兼容性结果，以及评分规则改进。详见[贡献指南](CONTRIBUTING.md)。测试采用临时项目和模拟 GitHub 响应，覆盖扫描边界、固定版本读取、证据校验、失败记录和 HTML 转义；不代表公网 API 可用性或推荐效果已得到验证。

如果这个流程对你有帮助，欢迎 Star，也可以在 [Issues](https://github.com/li3jia4hao5-hue/skill-radar/issues) 分享可复现的问题和建议。
